## 1. What the SEO changes do — in simple language

Think of SEO as helping Google understand your website, identify its pages, and display useful information when someone shares a link.

Your project now has several pieces working together. Here are the files and what each one is responsible for.

`www/pages/index.yaml` — the website's instruction sheet

It defines your site's name, pages, page descriptions, canonical website address, and which SEO features are enabled. The canonical address is currently `https://web4hub.github.io/web4-publisher/`.

Think of this as the master configuration.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/www/pages/index.yaml)

`scripts/validate-content.js` — the quality checker

Before the website is built, this checks the page configuration and publication details. It catches issues such as missing required fields, invalid article slugs, duplicate slugs, and incorrect SEO configuration.

It helps catch mistakes before publication.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/scripts/validate-content.js)

`scripts/generate-seo.js` — the website directory maker

It creates two important files: `sitemap.xml`, which lists pages search engines can discover, and `robots.txt`, which gives search crawlers basic instructions and points them to the sitemap.

It generates these files automatically during the build.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/scripts/generate-seo.js)

`index.html` — the default page information

It provides the website's initial title, description, canonical URL, social-sharing metadata, and structured data. This is the starting HTML document used by the build. [Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/index.html)

`scripts/prerender-seo.js` — the page-specific HTML maker

After Vite builds the site, this script creates HTML files for routes such as About and Blog, plus published articles. It puts each page's own title, description, canonical URL, social-sharing information, and structured data into its HTML. It also creates a `404.html` page marked `noindex`.

This matters because search engines and social platforms can read the page information before the JavaScript app runs.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/scripts/prerender-seo.js)

`src/App.jsx` — the live page updater

When a visitor moves between pages or opens an article, this updates the browser title, description, canonical URL, Open Graph and Twitter metadata, and JSON-LD structured data. Unknown routes are marked `noindex`. [Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/src/App.jsx)

`vite.config.js` and `package.json` — the build instructions

Vite uses the configured website path when preparing the production site. The `build` command runs validation, generates the sitemap and robots file, builds the website, and then creates page-specific SEO HTML. [Open `package.json`](https://github.com/web4hub/web4-publisher/blob/main/package.json) · [Open `vite.config.js`](https://github.com/web4hub/web4-publisher/blob/main/vite.config.js)

`.github/workflows/ci.yml` — the automated test checklist

GitHub Actions is configured to install dependencies, validate content, run tests, build the website, and check for generated SEO files and metadata. [Open the workflow on GitHub](https://github.com/web4hub/web4-publisher/blob/main/.github/workflows/ci.yml)

## 3. How to see the result

There are two ways: inspect the live website, or build it locally.

### Option A — inspect the generated files

Open these links in your browser:

Website

Check whether the deployed site loads.

[Open Web4 Publisher](https://web4hub.github.io/web4-publisher/)

Sitemap

See the page URLs listed for search engines.

[Open sitemap.xml](https://web4hub.github.io/web4-publisher/sitemap.xml)

Crawler instructions

See the robots rules and sitemap location.

[Open robots.txt](https://web4hub.github.io/web4-publisher/robots.txt)

Build and test status

Check GitHub Actions for completed or failed runs.

[Open GitHub Actions](https://github.com/web4hub/web4-publisher/actions)

If a link doesn't show the expected output, the latest changes might not yet be deployed, or the deployment may have failed.

### Option B — build and test it yourself

If you have the repository downloaded and Node.js installed, open a terminal in the project directory and run:

Bash

```
npm install
npm test
npm run validate
npm run build
```

The final command runs the full production build, including SEO generation. After it finishes successfully, look inside `dist/` for:

```
dist/
├── index.html
├── sitemap.xml
├── robots.txt
├── about/
│   └── index.html
├── blog/
│   └── index.html
└── 404.html
```

Published articles should also have their own generated HTML files beneath `dist/blog/`.

To inspect a generated page, open its HTML file in a text editor and search for `canonical`, `og:title`, `description`, and `application/ld+json`.

1. What the SEO changes do — in simple language

Think of SEO as helping Google understand your website, identify its pages, and display useful information when someone shares a link.

Your project now has several pieces working together. Here are the files and what each one is responsible for.

`www/pages/index.yaml` — the website's instruction sheet

It defines your site's name, pages, page descriptions, canonical website address, and which SEO features are enabled. The canonical address is currently `https://web4hub.github.io/web4-publisher/`.

Think of this as the master configuration.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/www/pages/index.yaml)

`scripts/validate-content.js` — the quality checker

Before the website is built, this checks the page configuration and publication details. It catches issues such as missing required fields, invalid article slugs, duplicate slugs, and incorrect SEO configuration.

It helps catch mistakes before publication.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/scripts/validate-content.js)

`scripts/generate-seo.js` — the website directory maker

It creates two important files: `sitemap.xml`, which lists pages search engines can discover, and `robots.txt`, which gives search crawlers basic instructions and points them to the sitemap.

It generates these files automatically during the build.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/scripts/generate-seo.js)

`index.html` — the default page information

It provides the website's initial title, description, canonical URL, social-sharing metadata, and structured data. This is the starting HTML document used by the build. [Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/index.html)

`scripts/prerender-seo.js` — the page-specific HTML maker

After Vite builds the site, this script creates HTML files for routes such as About and Blog, plus published articles. It puts each page's own title, description, canonical URL, social-sharing information, and structured data into its HTML. It also creates a `404.html` page marked `noindex`.

This matters because search engines and social platforms can read the page information before the JavaScript app runs.

[Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/scripts/prerender-seo.js)

`src/App.jsx` — the live page updater

When a visitor moves between pages or opens an article, this updates the browser title, description, canonical URL, Open Graph and Twitter metadata, and JSON-LD structured data. Unknown routes are marked `noindex`. [Open the file on GitHub](https://github.com/web4hub/web4-publisher/blob/main/src/App.jsx)

`vite.config.js` and `package.json` — the build instructions

Vite uses the configured website path when preparing the production site. The `build` command runs validation, generates the sitemap and robots file, builds the website, and then creates page-specific SEO HTML. [Open `package.json`](https://github.com/web4hub/web4-publisher/blob/main/package.json) · [Open `vite.config.js`](https://github.com/web4hub/web4-publisher/blob/main/vite.config.js)

`.github/workflows/ci.yml` — the automated test checklist

GitHub Actions is configured to install dependencies, validate content, run tests, build the website, and check for generated SEO files and metadata. [Open the workflow on GitHub](https://github.com/web4hub/web4-publisher/blob/main/.github/workflows/ci.yml)

For example, when you publish an article, the goal is for that article to have its own URL, title, description, canonical link, and `BlogPosting` structured data. When somebody shares it, the page's Open Graph information helps platforms choose the correct title and description.

These features improve how the site can be discovered and presented. They do not guarantee that Google will index a page or rank it highly.

## 3. How to see the result

There are two ways: inspect the live website, or build it locally.

### Option A — inspect the generated files

Open these links in your browser:

Website

Check whether the deployed site loads.

[Open Web4 Publisher](https://web4hub.github.io/web4-publisher/)

Sitemap

See the page URLs listed for search engines.

[Open sitemap.xml](https://web4hub.github.io/web4-publisher/sitemap.xml)

Crawler instructions

See the robots rules and sitemap location.

[Open robots.txt](https://web4hub.github.io/web4-publisher/robots.txt)

Build and test status

Check GitHub Actions for completed or failed runs.

[Open GitHub Actions](https://github.com/web4hub/web4-publisher/actions)

If a link doesn't show the expected output, the latest changes might not yet be deployed, or the deployment may have failed.

### Option B — build and test it yourself

If you have the repository downloaded and Node.js installed, open a terminal in the project directory and run:

Bash

```
npm install
npm test
npm run validate
npm run build
```

The final command runs the full production build, including SEO generation. After it finishes successfully, look inside `dist/` for:

```
dist/
├── index.html
├── sitemap.xml
├── robots.txt
├── about/
│   └── index.html
├── blog/
│   └── index.html
└── 404.html
```

Published articles should also have their own generated HTML files beneath `dist/blog/`.

To inspect a generated page, open its HTML file in a text editor and search for `canonical`, `og:title`, `description`, and `application/ld+json`.
